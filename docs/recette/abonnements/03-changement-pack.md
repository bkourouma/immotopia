# Recette abonnements — S3 Changement de pack

Écrit le 2026-11-09, **non rejoué**. Cadre, matrice de couverture et écarts transverses : voir [README.md](README.md).

Périmètre : ajout d'un pack (Agence puis Syndic), passage à l'Opérateur intégré, rétrogradation, retrait d'un pack, annulation d'un changement programmé, packs Patrimoine et Particulier, cycle mensuel / annuel, et ce que l'agence peut faire seule. Chaque résultat attendu est lu dans le code (fichier:ligne) ; quand le code contredit le plan ou paraît défectueux, le cas attend le comportement **réel** et renvoie à un écart `E-S3-k`.

## Réalité de l'environnement

- **Mode `enforce`** (instances de recette) : menus masqués, 403 `MODULE_NOT_INCLUDED` / `MODULE_READ_ONLY` / `SUBSCRIPTION_READ_ONLY`, 409 `QUOTA_EXCEEDED`. En `warn` : les gardes journalisent ce qu'elles auraient refusé et laissent passer (`packages/api/src/lib/subscription/guards.ts:25-40`), aucun quota ne bloque (`packages/api/src/lib/subscription/entitlements.ts:373-388`). En `off` : rien. **Les écritures d'abonnement** (`changePack`, `addSubscriptionItem`, `removeSubscriptionItem`) **ne lisent jamais** le mode : éléments, prorata, avoirs et montants sont identiques dans les trois modes (le mode n'est lu que par `getEntitlements`, `packages/api/src/services/subscription-v2-service.ts:417`). Seuls les refus de S3-16 (étapes 5 à 7) et de S3-23 (étape 6) exigent `enforce` ; le super-admin est dispensé des gardes (`packages/api/src/middleware/subscription-feature-middleware.ts:86-89`) : les sondes d'accès se font avec un compte de l'agence.
- **Cache des droits de 30 s** (`packages/api/src/services/subscription-v2-service.ts:364-371`) : attendre 30 s après une action du super-admin (`GET …/entitlements?fresh=1` renvoie la valeur à jour mais ne rafraîchit pas le cache de la page). `GET …/subscription/overview` recalcule toujours (`:1476`). La route historique `PATCH /api/admin/tenants/:id/subscription` n'invalide **pas** le cache (S3-29).
- **Tâche planifiée** `packages/api/src/jobs/subscription-usage-job.ts` (échéance : tous les jours à 02:30 UTC) : non déclenchable depuis l'interface. Elle émet la facture de la période suivante, applique les retraits et descentes programmés (`applyDueItemTransitionsTx`, `:208`) puis renouvelle ou passe `PAST_DUE` (`:221-253`). Pour S3-16 : appel de `processBillingBoundary` par un développeur, attente du passage de 02:30 UTC, ou — variante interface — « Marquer payée » une facture après l'échéance (`packages/api/src/services/platform-payment-service.ts:291-301` applique alors les mêmes transitions).
- **Création d'agence par l'interface = toujours un essai de 30 jours** (`docs/recette/SCENARIO_SYNDIC_ABONNEMENT.md:91`). Les agences « ACTIVE, période réglée » du tableau ci-dessous sont **préparées hors interface** (voir README) ; leurs dates sont des **valeurs de référence** : l'horloge est celle du serveur (`new Date()`), donc si le jour réel diffère, recalculer avec la formule ci-dessous (le jour d'action est compté, la fin de période exclue, heures ignorées : `packages/api/src/lib/subscription/pricing.ts:262-285`).
- **Un seul bouton de changement de pack dans l'interface** : « Passer au Pro » / « Passer à l'Essentiel » sur les packs Patrimoine (`apps/web/src/components/admin/tenant-detail/SubscriptionTab.tsx:863-867`). Tous les autres changements (Agence/Syndic → Intégré, descentes, retrait d'une pièce) passent par l'**API** (notée « API seule » : `curl` avec la session du compte super-admin du seed `create-super-admin.ts`) ou par « Ajouter » / « Retirer ». Voir E-S3-2.
- **Paiement en ligne** de la plateforme en mode `SIMULATOR` ; e-mails captés localement (rien ne part).
- **Libellés** : noms du catalogue en base (seed de `DEFAULT_CATALOG`, `packages/api/src/lib/subscription/catalog.ts:149-403`) : « Agence », « Syndic », « Opérateur intégré », « Patrimoine Essentiel », « Patrimoine Pro », « Particulier Gratuit », « Particulier Plus ».

### Formules de référence (vérifiées dans le code)

- Prix figé à l'ajout ; remise de combinaison = `round(min(prix de base des packs) × % / 100)` dès 2 packs distincts, extensions exclues (`packages/api/src/lib/subscription/pricing.ts:172-175`, `:198-213`) ; `%` par défaut 10 (`packages/api/src/lib/subscription/catalog.ts:94`).
- Prorata = `round(montant du cycle × jours restants / jours de la période)` (`packages/api/src/lib/subscription/pricing.ts:270-285`) ; annuel : montant mensuel × 11 (`packages/api/src/lib/subscription/pricing.ts:236-238`), période de 12 mois (`packages/api/src/lib/subscription/pricing.ts:252-256`).
- TVA = `round(HT × 18 / 100)` sur le total HT, jamais négative ; ligne `TVA 18 %` séparée (`packages/api/src/lib/subscription/pricing.ts:366-380`).
- **Aperçu** (`invoice-preview`) : lignes récurrentes (packs, extensions, remise), puis mises en route non facturées, puis lignes en attente dans l'ordre de création, puis `TVA 18 %` (`packages/api/src/services/subscription-v2-service.ts:1606-1666`) — **non triées**. **Facture émise** : lignes triées par nature `PACK, EXTENSION, DISCOUNT, PRORATA, SETUP, OVERAGE, USAGE, CREDIT, TAX`, tri stable (`packages/api/src/lib/subscription/platform-invoice.ts:57-74`, `:93-108`). Dans une même nature, l'ordre des lignes issues d'une même opération n'est pas garanti : comparer ces lignes comme un ensemble.
