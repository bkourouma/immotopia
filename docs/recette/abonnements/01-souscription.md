# Recette abonnements — S1 Souscription

Écrit le 2026-11-09, **non rejoué** (scénario rédigé d'après la lecture du code ; aucun navigateur lancé). Cadre, matrice de couverture et écarts consolidés : voir `README.md` de ce dossier.

Périmètre : création d'agence par le super-admin (tiroir « Nouvelle agence »), essai gratuit de 30 jours, invitation et première connexion de l'administrateur, première facture, paiement (simulateur et constat manuel), rappels de fin d'essai, prolongation d'essai, packs Particulier. Les ajouts d'extensions relèvent de la section S2 (`02-ajout-items.md`) ; les quotas, la grâce et la lecture seule relèvent d'autres sections.

## Réalité de l'environnement

- Instances de recette : `SUBSCRIPTION_ENFORCEMENT=enforce`, paiement en ligne de la plateforme en mode `SIMULATOR` (seule voie de paiement jouable ; le mode `LIVE` n'est pas jouable), e-mails captés localement, cache des droits d'agence de 30 s (recharger la page après une action du super-admin). Sources : `docs/recette/packs/CADRE_COMMUN.md` §2, `packages/api/src/config/env.ts:254` (mode par défaut `SIMULATOR`), `packages/api/src/services/subscription-v2-service.ts:364` (durée du cache).
- La facturation ne dépend pas de `SUBSCRIPTION_ENFORCEMENT` : `warn` et `off` ne changent ni les montants, ni les factures, ni le paiement ; ils ne changent que les gardes de modules et de quotas (`packages/api/src/lib/subscription/enforcement.ts:5`, aucune lecture dans `packages/api/src/services/platform-invoice-service.ts`). L'onglet « Abonnement » de la fiche agence affiche seulement l'alerte « Vérifications d’abonnement inactives » (`apps/web/src/components/admin/tenant-detail/SubscriptionTab.tsx:972`).
- La tâche planifiée `packages/api/src/jobs/subscription-usage-job.ts` (passage complet à 02:30 UTC, alertes à :15 chaque heure, `:615-616`) **n'est pas déclenchable depuis l'interface**. Elle seule : génère et émet la facture de fin d'essai, passe l'abonnement en `PAST_DUE`, envoie les rappels J-7 et J-1. Pour la provoquer sans attendre : (a) attendre le passage de 02:30 UTC ; (b) un développeur appelle `triggerSubscriptionUsageCycle({ now, tenantId })` (`:628`, `now` peut simuler une date future) ; (c) pour voir la facture sans job, un développeur ramène `trialEndsAt` dans le passé par `PATCH /api/admin/tenants/:tenantId/subscription/settings` (le schéma accepte toute date, `packages/api/src/controllers/subscription-v2-controller.ts:186-193`) puis le super-admin clique « Générer une facture » (la génération n'est refusée que si la fin d'essai est future, `platform-invoice-service.ts:671-676`). Aucun de ces gestes n'a de bouton.
- Les envois d'e-mails (invitation, facture, rappels) sont lus dans le récepteur local de l'instance ; aucun message ne part.
- Le tiroir « Nouvelle agence » n'expose que : packs, extensions `EXT_LOTS_10` / `EXT_COPRO` / `EXT_CHANTIER` / `EXT_BIENS_10`, cycle, mise en route (`apps/web/src/components/admin/CreateTenantDrawer.tsx:468-532`). Les autres entrées (ancien format `modules`, `type`, extensions inventaire et signatures, packs Particulier) ne se jouent que par l'API (`POST /api/admin/tenants`) ; chaque pas concerné est marqué « API seule ».
- Les dates ci-dessous sont un **exemple de fil rouge** : agence créée le 2026-11-09 à 10:00 UTC. Le jour de la recette, recalculer les dates à partir de l'heure réelle de création (la fin d'essai est `création + 30 × 24 h`, `packages/api/src/services/tenant-provisioning-service.ts:197-199`).
- Aucun mot de passe n'est écrit ici : le compte super-admin est celui du seed `packages/api/prisma/seeds/create-super-admin.ts` ; le mot de passe de l'administrateur d'agence est choisi à l'acceptation de l'invitation (règle : 8 caractères, une majuscule, une minuscule, un chiffre, un caractère spécial, `apps/web/src/pages/auth/AcceptInvitePage.tsx:277-285`).
